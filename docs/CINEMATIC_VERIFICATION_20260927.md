# 入场与陨落展示检查（2026-09-27）

本次仅修改本地表现时序及首次破损渲染，不改变规则、难度或模型外观。预览仍为 http://127.0.0.1:8792/ ，未推送、创建 PR 或发布。用户本人试玩后明确批准发布的条件继续有效。

## 查明并修复的问题

- 正常入场已经预留两秒；冷加载、重开和换级均通过。开启“近看飞船”后，检视位置却覆盖了入场和陨落运动。现在新局和终局自动回到战斗视角，检视变换也不能覆盖正在入场或坠落的飞船。
- 四连击致胜时，原来的固定终局时间会先陨落、再出现第四次命中。现在按实际攻击段数延后终局，最后命中后才开始陨落；从实际陨落开始，以场景渲染时钟再留足两秒，然后放行结算弹窗。重开会取消旧时间线。
- 首次出现隐藏的破损碎片时，实测有一次 53ms 长任务，其中渲染管线 CPU 调用占约 52.4ms。现在各级飞船加载时，通过实际 MRT/bloom 管线预热完整舰体、破损碎片和复用特效，并在显示画布前恢复干净的入场帧。

## 验证

85 项基础测试、类型检查、构建通过；同一次浏览器回归的 8 项全部通过，涵盖冷加载、换级、近看冲突、四连击致胜、真实完整人机对局、重复输入、重开取消、减弱动效、五种视口、WebGL/缺模型降级、16 艘敌舰加载和我方破损。

实际对局中抓取零血陨落画面，确认六块碎片可见，中央没有结算或开局面板覆盖；结算弹窗在陨落开始约两秒之后出现。入场、我方破损及实际对局陨落截图已人工查看。

同机 Chrome/WebGPU，1920×1080、设备像素比 1.25，按固定表现事件顺序采样：

| 场景 | 优化前最大帧间隔 | 优化后最大帧间隔 | 优化后长任务 |
| --- | ---: | ---: | ---: |
| 四次命中、六次回血、三张牌充能 | 34.9ms | 27.7ms | 0 |
| 重复上述特效 | 34.5ms | 21.3ms | 0 |
| 首次破损陨落 | 52.3ms | 28.0ms | 0 |

首次破损场景中，渲染管线 CPU 调用的最大耗时由 52.4ms 降至 1.1ms，符合预热消除首次上传/编译停顿的预期。完整机器证据、原始日志路径与源文件 SHA 见 [cinematic-timing-verification.json](qa/cinematic-timing-verification.json)。

## 范围与限制

这是短时、同机、合成渲染负载的对比，不能据此保证所有设备都不卡顿，也不是持续帧率测试。空闲帧 p95 在两次采样间由 17.6ms 波动到 20.9ms，因此不作整体 FPS 提升的结论。预热把工作移到加载期，首次加载可能稍长。减弱动效与舰图降级仍按原设计快速放行。已有玩法模拟结果继续有效，本轮没有调整数值或重跑平衡实验。
